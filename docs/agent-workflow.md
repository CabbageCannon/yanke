# Agent 工作流 SOP

2026-10-21 修订，适用于所有研发 Agent。
替代旧版“PM 只建议、人工装环境、人工合并和确认 HANDOFF”的工作方式。
授权与优先级见 AGENTS.md；用户最新明确指令高于仓库规范。

## 1. 角色

| 角色 | 职责 | 边界 |
|---|---|---|
| 主控 PM / 研发 Agent | 规划、技术把关、任务、分支、集成、PR / 合并 / 部署、HANDOFF | 代码实现必须分派子 Agent / 子任务 |
| 实现 Agent | 读取上下文，在分派分支 / worktree 实现、自测、写 result | 不擅自改范围、切共享目录分支、操作远程 main |
| 独立审查 Agent | 读代码、任务、diff 和回报，验证逻辑与风险，写 review | 独立上下文，不改实现文件 |
| 用户 | 提供无法取得的秘密 / 交互验证，裁定产品冲突、重大架构变动，反馈体验 | 不承担常规安装、配置、排错、逐卡审批 |

主对话统一沟通；子任务疑问由主控解决或汇总。
主控可直接改规范、规划、任务卡、交接；代码和配置实现交子任务。
不能把格式检查当功能验证，不能把未测项写成通过。

## 2. 启动

1. 按 AGENTS.md 阅读，检查 git status、分支、远程和已有产物。
2. 保留用户改动，不自动清理未知修改。
3. 在主对话简述状态、目标、风险和确需输入的问题。
4. 不等待启动报告确认，直接执行已授权工作。
5. 先建分支再分派；用户明确的前置提交必须先完成，不能夹带正式开发。

## 3. 任务卡

目录：docs/tasks/dayN/TXX-<topic>.md；对应 .result.md 和 .review.md。
编号项目内唯一。按逻辑目标拆分，三文件 / 三百行仅作参考，不是审批门槛。
脚手架、锁文件、迁移可超出参考值，说明必要性。

卡片最少含：

```markdown
# TXX 任务名称
- 阶段 / 分支 / 基准提交：
- 依赖与可并行性：
- 目标：
- 可修改 / 新增的文件或目录：
- 禁止写入范围：
- 必要依赖与配置权限：
- 验收标准、验证命令：
- 非目标：
- 回报路径：
```

读取必要上下文不受写入白名单限制。
合理关联改动由主控修订卡片即可，不要求用户另批依赖或文件数量。
实现回报写：完成 / 部分完成 / 阻塞、实际文件、命令与结果、偏离、风险、待测项、建议 commit。
主控不冒充实现者补写通过结论。

## 4. 分派与集成

1. 主控建 codex/<type>-<topic>，记录基准。
2. 向实现 Agent 提供任务卡、工作目录 / 分支、禁止并发操作和回报要求。
3. 实现自测交 result；主控检查范围和证据后分派独立审查。
4. 审查以独立上下文读相关代码和 diff，必要时重跑检查。
5. 阻塞问题交原实现者修复并复查；技术分歧由主控复现裁定，不自动交用户。
6. 主控更新 HANDOFF、提交 / push / PR，适用检查通过后自主合并。

默认串行。共享目录禁止多 Agent checkout、提交同一 index 或写同一文件。
并行实现必须用不同 worktree / 分支，且没有未稳定接口依赖。
审查期间冻结被审查代码；主控与子任务不能同时改同一文件。
工具缺少子 Agent 时用可用独立子任务；若均不可用就记录限制、准备卡片，不能冒充独立上下文。

## 5. 审查门槛

独立审查至少检查：

1. 当前 PRD、任务和上下游行为一致。
2. 错误处理、边界、重复操作、数据完整性。
3. Auth / RLS、秘密边界、位置隐私。
4. 类型、lint、规则测试、打包证据和未测原因。
5. 设计 token、基本可访问性和 MVP 范围。
6. 依赖真实可安装，并与 Expo / React Native 版本兼容。
7. 回报和 HANDOFF 与实际一致，Git 不含秘密 / 产物。

结论：通过 / 有条件通过 / 不通过。
有条件通过仅留非阻塞问题，写明记录；逻辑错误、秘密暴露和失败检查不能带过。
主控不能无证据忽略不通过；可复现后要求补充或更正审查。

状态：planned → in_progress → self_tested → under_review → ready → merged。
blocked 必须有具体依赖，可继续独立工作。
合并需要独立审查和适用检查；纯文档阶段不要求不存在的应用测试。
缺设备的真机流程记待验证，不用 Web 代替，也不强制用户逐卡亲测才能继续。

## 6. 自主排错与升级

依赖下载、CLI、构建、Schema / ADR / 工作流修改、账号和部署配置由 Agent 自主处理。
先调查已有登录与工具，必要时安装，不直接给用户一串待执行命令。

只在以下情况请求输入：

- 无法取得的 Key / URL / 账号资料，或 MFA / 邮箱确认等仅用户可做的验证。
- 产品冲突、重大架构变更或 MVP 范围变化。
- 平台实际拒绝权限，或超出授权的不可逆操作。

报告写问题、尝试、影响、建议、用户最小动作；只等待依赖该回答的工作。
时间过去不等于用户同意。账号 / 云部署没有成功证据就不能声称已完成。
凭据不得写进回报、日志或 Git。

## 7. 收尾与接力

每阶段（包括带外部阻塞的阶段）更新 HANDOFF：

- 当前阶段、分支 / PR / 可追溯提交、任务快照。
- 已交付产物、实际验证、未测平台 / 流程。
- 半成品、具体阻塞、限制与下一步。

方向决策追加 docs/decisions.md，详细过程留任务回报 / SUMMARY。
主控自行提交 HANDOFF，不等用户确认；不把文档存在当运行证据。
切换 Agent 只需指明“先读 AGENTS.md 和 HANDOFF.md，继续已授权工作”。
项目不能依赖某个厂商聊天历史、私有工具名或本机绝对路径才能理解。
