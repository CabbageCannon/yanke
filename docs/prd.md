# PRD v0.4 — 研刻 YanKe

2026-10-21，当前版本用于 MVP 实现与验收。状态与验证以 HANDOFF 为入口。
用户于2026-10-21确认：实时打卡无迟到宽限；总结可选，可直接完成。决策见ADR-014；规则确认不代表业务功能已实现。

## 1. 产品与目标

面向考研备考人的极简学习计划 App。
核心闭环：周网格 → 创建学习计划 → 可选高德地点围栏 → 时间窗口打卡 → 按规则记录时长 → 手动完成（可选小总结）→ 统计。
示例：点击空白格创建9:00–11:00数学，可绑“图书馆200m”；在时间和地点条件满足后打卡，手动完成，可写一句总结。

第一周不做社交、防作弊、轨迹、手机号验证码。
不自动承诺第二周社交；通知、拖拽、重复 / 复制 / 顺延等只记候选。

## 2. 核心对象

- User：Supabase 邮箱账号，只读写本人数据。
- Plan：日期、科目、可选标题、开始 / 结束时间、可选围栏、状态和总结。
- CheckIn：必须关联本人计划，每计划最多一条；normal / late / makeup 三类。
- Geofence：计划内嵌的一个地点名、GCJ-02 中心和半径。多个计划可选择不同地点。
- 不保存用户实际坐标、轨迹、后台定位或离开事件。

## 3. 页面

### 3.1 周时间表

- 默认进入本周，周一至周日七列，纵轴8:00–23:00；主线每小时，点击粒度30分钟。
- 可切上一周 / 下一周和回到本周；今日列头高亮，今日当前时间线克制显示。
- 点击空白格直接打开计划表单，预填日期与起始时间；点击计划块看详情和可用操作。
- 计划块只显示科目、时间和必要状态，科目低饱和色；完成有勾选标记，不只靠颜色区分。
- 重叠计划允许保存并提示，展示必须能分别点击；不要求第一周拖拽改时。
- 空状态：“点击任意空白格，创建你的第一个学习计划”。

### 3.2 计划表单与详情

- 科目：数学 / 英语 / 政治 / 专业课 / 其他；标题可选。
- 日期和开始 / 结束时间；结束晚于开始，最短15分钟，不跨所记录时区自然日。
- 第一周沿用8:00–23:00可见网格，表单限定当地08:00≤开始<结束≤23:00，防止保存不可见计划；全天网格另记候选。
- 围栏默认关闭；开启后必须选定地点与半径，未完成选点不能保存成有效围栏。
- 详情提供编辑、可选绑定地点、实时打卡、补卡、完成 / 总结、删除，按状态显示。
- 删除为软删除，时间表隐藏；已有打卡历史保留，账号注销为另一个受保护操作。
- 未打卡手动完成沿用旧规则：可计完成，时长为0；不能因此生成虚假打卡或增加连续天数。
- 已打卡后变更计划时间 / 科目不得重写历史时长和日期快照；具体编辑限制由实现任务明确。

### 3.3 高德选点

- 通过鉴权服务端代理搜索高德 POI；返回候选名称和地址，选择后回填。
- 半径50–1000m，默认200m；不强制第一周实现复杂地图编辑交互。
- 原生定位与 POI 坐标均为 GCJ-02；如来源不同必须转换后再判断。
- 围栏判定距离≤半径；定位失败 / 拒绝权限提示重试或系统设置，不伪造打卡。
- 无围栏计划不申请位置权限，只校验时间。
- 仅一次前台定位，不后台持续检查；本版不验证模拟定位。

### 3.4 实时打卡

实时打卡只在时间窗口内允许；有围栏还需位于范围内。
以下规则已经用户确认，供后续实现与验收；t为服务器实际打卡时刻：

| 规则 | 边界与时长 |
|---|---|
| 实时窗口 | [start_at−15分钟, end_at)，结束时刻排除 |
| normal | start_at−15分钟≤t≤start_at，取完整计划分钟 |
| late | start_at<t<end_at，取 end_at−实际打卡时刻的分钟 |
| 宽限 | 无；开始后立即按late处理 |
| 结束后 | 不再实时打卡，使用符合条件的补卡 |

实现后统一以服务器时刻计算；分钟向下取整，不产生负数；结束前不足一分钟可能记0分钟。
重复点击不能生成第二条，失败不能先显示成功。打卡本身不等于完成计划。

### 3.5 七天补卡

- 仅针对没有打卡的本人计划，计划结束起连续168小时内可以手动补卡。
- 实现约定区间 [end_at, end_at+168小时]，包括两端；与结束时刻关闭实时打卡的规则衔接。
- 输入整数分钟1–1440，小总结可选，不要求定位；不按计划时长强行截断用户填写值。
- 生成 makeup，归原计划学习日期，不能用补卡提交日替代。
- 已有 normal / late / makeup 不能再叠加补卡；过期明确提示。

### 3.6 完成与小总结

- 用户可直接手动完成；也可填写小总结，系统不自动生成文本、不自动弹出打断学习。
- 提示“今天学了哪些知识点？”，文本去首尾空白，建议上限280字。
- 总结可选，留空或仅空白不阻止完成；有内容时去首尾空白后保存，不生成占位总结。
- 打卡和完成是两个动作；完成状态与总结应原子保存，失败不留下半状态。
- 第一周不做自动结束或离开围栏自动结算。

### 3.7 统计

| 指标 | 口径 |
|---|---|
| 科目累计时长 | 累加有效 checkins.duration_minutes；无打卡完成为0，不按格子数量推算 |
| 完成率 | 同区间同一非删除计划集合中 completed 数 / 该集合总数，包含未来计划 |
| 无计划 | 显示“—”，避免0/0或误报100% |
| 连续打卡天数 | 按原计划学习日期去重，连续日期计数，不能同一天多卡叠加 |
| 今日无卡 | 可从昨天起算，避免今天尚未学习就立刻清零 |
| 补卡 | 时长和日期归原计划，可补齐历史连续日期 |
| 删除 | 隐藏计划并同时排除完成率分子与分母，已有打卡仍计历史时长 / 打卡天数 |

默认按本周展示时长 / 完成率，允许查看累计；连续天数从截至今天的历史有效打卡日期计算。
补卡未来日期或造出重复日期记录不合法。详细统计查询在后续任务实现，基础 view 不代表所有指标已交付。

### 3.8 邮箱账号

- 邮箱 + 密码注册、登录和退出，邮箱确认按 Supabase 真实配置验证。
- 未登录不得读取个人计划；会话持久化后正常打开默认进入时间表。
- 不做手机号验证码；邮箱验证码登录不是第一周前置。
- 退出或切换账号必须清理个人缓存；注销需服务端删除 Auth 账号与本人数据，不能仅清本地。

## 4. 时间、异常与隐私

- 时间存 UTC timestamptz，展示沿用设备本地时区；创建计划冻结 IANA 时区和学习日期语义。
- 离线 / 失败保留当前界面，写操作明确失败和重试，不虚报已同步；离线写队列不在 MVP。
- 首次无云配置可展示基础骨架，但不能伪装已登录或已保存。
- 定位拒权只影响绑地点的实时打卡，补卡和无围栏路径不依赖定位。
- 原生系统必要的静态启动画面简洁处理；不做自定义启动页 / 动画。
- “秒开”为目标，需设备实测冷 / 热启动，不以 Metro / Web 打包作为证据。
- 上线前需真实的权限用途说明、隐私说明和账号注销路径，不把法律合规交给占位文本。

## 5. 核心验收

1. 邮箱注册 / 登录，未登录不能读取本人数据；用户A不能读写用户B数据，退出后不残留。
2. 空白格创建9:00–11:00数学，正确落格；重启保留，改时更新，删除隐藏。
3. 可选绑定“图书馆200m”，保存后详情正确；不绑定也可以走时间窗口打卡。
4. 有围栏且在范围内 + 时间合法，生成唯一打卡；范围外 / 时间外不生成。
5. 9:00–11:00计划：8:45和9:00打卡均记120分钟；9:01记119分钟；8:45前及11:00起不能实时打卡，无迟到宽限。
6. 结束3天后无记录，可补90分钟，附或不附总结均可；超168小时拒绝；重复补卡拒绝。
7. 不填写总结或只输入空白均可直接完成；填写时保存完成标记和去首尾空白后的原文，失败不留下半状态。
8. 两次正常数学各120分钟累计240；迟到、补卡、无卡完成、删除的指标按口径准确。
9. 同日多卡只计一个打卡日，补卡归原学习日，今日未卡与跨周连续计数正确。
10. 无后台位置 / 轨迹记录，Web Key 不在客户端；原生定位、权限和构建在实际设备验证。
11. 空 / 加载 / 网络错误、重叠计划与系统字体放大可操作；无额外启动流程。

## 6. 已确认规则与实施边界

- 用户已确认无迟到宽限、总结可选；这两项不再阻塞后续业务RPC和页面设计。
- 补卡精确端点为实现约定，见§3.5；后续任务需覆盖时间端点与空总结，不把规则文字当功能验收。
- 基础 Schema 不开放任意客户端写打卡时长；最终 RPC、POI 代理、Auth UI 和全部业务页均需后续实现与验收。
- 本地 JS 打包、SQL stub 检查、真实云端和原生设备是不同证据层级，分别记入 HANDOFF。
