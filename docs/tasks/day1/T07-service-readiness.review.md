## 审查结论

- 目标保护：脚本缺少任何必需配置即失败；项目 ref 格式、精确 HTTPS 项目 URL 和重复 ref 的显式确认均在首次请求前验证。管理员 API 只在显式 `admin` 调用使用 service_role；普通用户路径使用 anon Key 加实际用户 token，双用户 RLS 断言没有被管理员权限替代。
- 身份与清理：随机 `example.invalid` 沙箱、随机强密码、管理员确认邮箱，不发送注册邮件。用户 ID 在登录前加入本轮清单；后续失败仍进入 `finally`。清理仅删除该清单中的 Auth 用户，随后按对应 ID 验证三张表级联为空，不删除原有账号或单独保留的 UI 验收账号。清理失败使进程失败。
- 覆盖与证据：11 个检查组覆盖实际 Auth / refresh、profile 触发器、匿名拒绝、JWT 下的双用户行隔离、列 grants、计划约束、直接打卡 / 硬删拒绝、可信快照与外键、统计视图及软删。断言与既有迁移一致；result 对真实云验证和 PGlite 桩、App UI、邮件、RPC、原生定位的边界描述正确。
- 配置与秘密：本地 `config.toml` 选择 PG17、邮箱确认、关闭手机 / 匿名注册及无关服务，未冒充已推送云设置。集成 README 给出原生 Node 重放与显式配置合同；依赖已有迁移和明确测试目标，不内嵌秘密。根忽略规则覆盖服务、客户端和 UI 沙箱环境文件，Supabase 忽略规则覆盖本地链接状态。脚本不输出请求头、响应体或完整会话；断言错误只涉及状态、错误码与测试字段。
