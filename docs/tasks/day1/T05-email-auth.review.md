## 核对结果

| 范围 | 结论 |
| --- | --- |
| 客户端配置 | 只接收 URL 与 publishable / anon Key；识别并拒绝 secret / service_role，拒绝远程明文 HTTP、URL 内凭据 / 查询参数。app.config.ts 分别检查两个客户端 Key 变量，避免备用变量误放服务端 Key 后被优先项掩盖；错误不输出 Key。 |
| 静态渲染 / 持久化 | 客户端在挂载后创建，SSR 不启动 AsyncStorage 读写。单例官方客户端开启持久化与刷新，关闭 URL 自动提取会话；缺配置走只读时间表，不伪造登录或发个人数据请求。 |
| 登录 / 注册 | 先校验邮箱与注册密码，保留密码原值；重复提交互斥。注册无 session 时保持未登录并提示确认邮箱；不把注册响应当成个人页面访问许可。服务端原始错误不会直接展示。 |
| 身份边界 | scope 仅在 signedIn 提供；身份变化递增版本，AuthGate 按 scope.key 重挂个人子树。异步恢复 / 登录响应有请求与事件版本保护，旧响应不能覆盖新账号。相同用户 TOKEN_REFRESHED / 重复 SIGNED_IN 保留 scope，不重置编辑状态。 |
| 退出 / 失败 | 发退出请求前先撤销 scope、清空 session 并移除个人子树；失败进入阻断页面且可重试。旧用户 refresh 不能恢复已退出 / 已切换身份；外部 SIGNED_OUT 使在途认证响应失效。 |
| 生命周期 | effect 有 disposed 检查；store 取消 Auth 订阅并使旧 scope 失效，provider 移除 AppState 监听并停止刷新。事件回调仅同步更新状态，不在 TOKEN_REFRESHED 回调内递归刷新。 |
| 依赖 / SDK | 核对实际 auth-js 2.118 源码与随包 lockless-coordination 迁移说明：未设置过时 processLock 符合当前 SDK 默认协调方式。timegrid 仍精确固定 0.2.2；宽度由容器 onLayout 非零后传入，避免 SSR 初始零宽度网格。 |
| 页面 / 视觉 | 登录 / 注册、退出、恢复失败重试均接入真实 provider；主题、密码遮蔽、输入标签、触控高度和滚动 / 键盘避让均具备。独立查看作者的 login-320.png 与 no-config-week-fixed-390.png，控件可见，网格与低饱和风格一致。 |
| CI | npm run test:auth 是应用检查的正式步骤，执行真实 15 项测试，无缺云配置跳过；Web 静态导出继续运行，不把纯逻辑替身当云端验收。 |

当前没有计划数据请求；T06 接入后仍必须在异步回填前同时检查 scope.isCurrent() 与组件挂载状态。scope 不能替代数据库 RLS。持久化会话的本地 user 字段只用于页面状态，服务端授权仍依赖有效 JWT / RLS。
