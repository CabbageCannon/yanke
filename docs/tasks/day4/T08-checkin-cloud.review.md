## 核对结论

- **目标保护与 TLS**：首次网络操作前验证全部必需配置、精确项目 URL / ref 和显式重复 ref 确认。数据库只读取被忽略的 CLI pooler 链接，要求 `postgres.<ref>`、Supabase pooler 域名和5432 session端口；不接受 transaction pooler。连接前从固定官方 HTTPS 地址读取 CA，核对固定 SHA-256 指纹并保持 `rejectUnauthorized: true`，没有跳过证书验证或把密码放进输出。
- **真实身份与参数**：管理员权限只用于本轮身份创建 / 清理，四个业务 RPC 使用随机沙箱的实际 GoTrue token。写函数使用单对象 Accept，连续天数验证数值返回；数字小数、非有限、空及范围外值经 PostgREST 实际提交。返回断言覆盖 normal / late、重放、补卡冲突、总结保留 / 清空 / 原子失败及身份隔离，与已审 RPC 合同一致。
- **争锁证据**：独立 locker 在事务中持有本轮计划的行锁，再发出4个HTTP RPC；monitor 递归追踪以该 locker PID 为根的阻塞链，按函数名筛选并计数不同等待锁的后端，至少观察到2个才放行。随后核对实时4次结果唯一，补卡一次成功加三次23505并核对库中只有一条。因此测试设计能够区别客户端并行与实际 PostgreSQL 事务争锁。
- **失败收集与释放**：并发请求创建时立即挂接 `Promise.allSettled`，观察失败仍进入 `finally` 提交释放行锁，然后等待本批结果再报告观察失败。外层 `finally` 关闭两个数据库连接并执行身份清理；连接本身失败会使最终结果失败，不伪报通过。网络 / COMMIT / 进程中断故障注入未执行，不能将源码处理写成所有故障已验收。
- **清理与范围**：仅将本轮管理员创建的身份加入清单，登录前就登记 ID；最终逐个删除该清单并按 ID 核对 profiles / plans / checkins 级联为空。脚本不遍历或删除既有 UI 沙箱，计划锁也只针对本轮新计划。输出省略响应体、会话、连接串及请求头。
- **结果边界**：result 明确记录实际云8组退出0、实时2个 / 补卡4个后端争锁和2/2身份清理；相关数据库 / README 内容一致。云测试使用真实当前时刻创建合法窗口，不修改生产时钟。精确时间端点仍来自独立审过的本地42组，不把云当前窗口冒充精确端点测试。
