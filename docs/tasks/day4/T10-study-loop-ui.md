# T10 打卡 / 补卡 / 完成与统计客户端

- 状态：planned；待T06计划CRUD与T08 RPC稳定并由主控建立新分支后分派。
- 阶段 / 分支 / 基准：Day 4 / 5；计划codex/feat-study-loop-ui，实际基准在开工时记录。主目录串行实现，其他任务不得同时改业务文件。
- 依赖：T05会话scope、T06计划数据 / 表单、T08四RPC与现有统计view。准确接口见docs/database.md及迁移，不臆造参数或返回。
- 目标：从计划进入实时打卡、七天补卡、手动完成 / 可选总结；查看本周 / 累计科目时长、完成率和连续打卡天数，贯通无围栏学习闭环。
- 写入范围：app/、src/、必要scripts/测试 / CI、同目录result；不改已冻结迁移、PRD、HANDOFF或第三方秘密，不操作Git。
- 实时：只调用check_in_plan，由服务器计算normal / late与分钟；展示返回类型 / 时长，重复请求不多加记录，打卡不自动完成。无围栏不申请定位；有围栏仅在真实前台判断通过后传true，定位尚未集成时明确暂不可用，不能默默跳过围栏。
- 补卡：整数1–1440分钟，输入错误在提交前提示；服务器执行[end,end+168小时]边界。可选总结与补卡一起保存，不自动完成，不叠加已有记录；失败保留输入，网络不确定成功时先读现状再提示重试，不能虚报或累计重复时长。
- 完成：无卡亦可直接完成、时长0；有内容去首尾空白后原子保存。总结预填已有内容，省略/null保留、显式空白清空，280字为建议、2000个PostgreSQL字符为安全上限，不能用UTF-16 code unit意外截断中文以外文本。完成后可编辑总结但不能使已删除计划复活。
- 统计：默认本周，可看累计；按study_date过滤并聚合view，不平均每日完成率。分母为0显示“—”，未来计划包含在同集合，软删排除完成率但保留历史分钟 / 打卡天；各科目含0的清晰展示。连续天数调用get_checkin_streak并传设备观察日。
- 会话 / 异步：所有读写和错误回填检查当前scope及请求序号；切周、退出、卸载时旧请求不能覆盖新界面。操作成功刷新计划 / 打卡与相关统计；失败保留可重试草稿，避免保存旧编辑草稿覆盖新的completed状态 / 总结。
- 界面：沿用深墨绿与科目token，不添加新启动流程或复杂动效；计划块完成有文字 / 勾选状态。320 / 390窄屏和字体放大可操作，加载 / 空 / 离线 / 错误有清晰路径。
- 验收：必要规则测试；lint / typecheck / Expo检查 / Web导出；真实测试账号浏览器验证实时打卡 / 重放、结束后补90分钟 / 重复拒绝、无总结完成、编辑 / 清空总结、无卡完成0分钟、本周 / 累计统计、软删历史保留、退出重载隔离。精确时间端点引用T08已验证测试，不为浏览器调试修改云时钟或生产RPC。
- 非目标：POI代理或新定位框架、社交、防作弊、轨迹、通知、自动完成、离线写队列、生产发布。
- 回报：docs/tasks/day4/T10-study-loop-ui.result.md，记录真实流程、截图位置、命令结果与未测项；完成冻结后独立审查。
