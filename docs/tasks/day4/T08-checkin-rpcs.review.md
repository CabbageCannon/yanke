## 正确性与权限

- 四个 RPC 均固定空 `search_path` 并采用 `security definer`；显式撤销 public / anon / authenticated 默认 execute 后仅授予 authenticated，函数内再次拒绝空 `auth.uid()`。调用者不能指定用户 ID；写入口查本人非删除计划，未知 / 他人 / 已删除对象统一报错。直接 `checkins` 客户端写权限仍未放开。
- 三个写入口在读取计划后保持 `FOR UPDATE`，与计划直接编辑 / 软删及其他 RPC 对同一计划的写入串行；实时与补卡均在锁后读 `clock_timestamp()`。实时入口不接受客户端时间或分钟数，重复请求先返回原记录；补卡重复明确冲突。唯一约束和同用户复合外键继续兜底。
- normal / late 和补卡的精确端点符合任务；迟到向下取整且允许0分钟，无宽限。补卡 numeric 在 integer 转换前排除小数、非有限和范围外输入。围栏仅要求明确 true，未绑定围栏不依赖定位；这符合已确认的自律边界，未引入实际位置存储或防作弊能力声明。
- `complete_plan` 不伪造打卡，不要求先打卡；补卡不自动完成。总结省略 / null 保留原值、空白清空、有内容修剪后覆盖，2000字符上限和原子失败行为与冻结合同一致。
- 连续天数只查本人快照日期，去重后从今天或昨天起算，排除未来日期；排序后的日期与行号差值确保遇断档即停止。0分钟有效卡、软删历史保留、补卡归原日、单独完成不加天数均有对应检查。

## 保留边界

- PGlite 的 Auth / JWT 角色为桩；本次没有验证新增 RPC 的真实 JWT / PostgREST 参数解析、云端 PG17 或部署状态。T07 的基础11组真实检查不能替代它们。
- 八个快速重复请求在 PGlite 单连接排队，只验证同一结果 / 唯一记录。源码行锁与唯一约束合理，但独立连接的真实争锁、重复请求和并发编辑仍应在集成后的明确云端验收中验证。
- 无 App 页面、POI、原生定位或设备验收；本次通过只授权服务端代码进入集成，不代表完整 MVP 已交付。
