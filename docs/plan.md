# 技术与交付计划

## 执行顺序

2026-10-21 新需求生效。七天是 MVP 工作分解，不代表未知账号、签名与设备条件可无条件在七个自然日完成。
先修订规范并提交 GitHub，再细化架构和初始化 Expo。现有仓库不重复 clone。
主控负责规划和集成；代码通过新分支和子任务完成，每阶段更新 HANDOFF。

## 技术栈

- Expo + React Native + TypeScript + Expo Router。
- Supabase 邮箱 Auth + Postgres，RLS 隔离。
- 优先 @symbiot.dev/react-native-timegrid，核查实际包、API、peerDependencies 和兼容性。
- 高德原生前台定位 + POI 选点；Web 服务 API 通过鉴权服务端代理。
- 围栏只用一次位置，双方坐标系必须一致，不保存轨迹。

架构已补入 docs/architecture.md，具体版本以 T01 / lockfile 为准；候选库不能当已验证。
Agent 自主完成依赖 / CLI、环境、账号配置、云部署；缺必要私密信息再升级。

## 风险处理

| 风险 | 处理 |
|---|---|
| timegrid / 高德桥接不兼容 | 先实际核查，既定能力内选兼容版本，重大替换再升级 |
| Expo Go 缺原生模块 | 使用 development build，Web 只验 JS |
| 缺云配置 / Key | 继续独立任务，汇报所缺配置名、用途和安全提供方式，不披露密钥或伪造成功 |
| Windows 无本机 iOS 编译 | 按条件用 EAS / Apple 签名，缺条件记待验证 |
| Supabase 网络 | 实测连接，不预设国内可达性和固定延迟 |
| 产品规则冲突 | 先澄清，不实现矛盾逻辑 |
